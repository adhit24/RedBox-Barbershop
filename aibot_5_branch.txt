1. ANALISIS AWAL — ARSITEKTUR EXISTING
================================================================================

Ada 2 sistem webhook yang menangani WhatsApp:

A) Fonnte Webhook (api/wa/webhook.js)
   - Vercel serverless function
   - Menggunakan Fonnte sebagai gateway WhatsApp
   - Sudah punya human takeover logic via:
     - Local Map (humanTakeoverMap) — in-memory per instance
     - Supabase table (wa_paused) — cross-instance persistence
   - Multi-branch: 5 cabang (Bypass, Sumber, Samadikun, CSB, Tegal)
   - Deteksi admin: via field isFromMe pada outgoing message

B) WhatsApp Cloud API (server/whatsapp-ai/)
   - Express server standalone
   - Menggunakan Meta WhatsApp Cloud API
   - Punya handoffStore.js — file-based (handoff.json)
   - Deteksi admin: via message status updates (sent/delivered/read)
   - Tiap cabang jalankan instance sendiri

Masalah: Kedua sistem punya handoff logic sendiri-sendiri, tidak shared.
         Kalau admin takeover di satu cabang, cabang lain tidak tahu.

3. SUPABASE TABLE — wa_paused
================================================================================

CREATE TABLE IF NOT EXISTS wa_paused (
  sender text PRIMARY KEY,          -- nomor WA customer (normalized, digits only)
  paused_until timestamptz NOT NULL, -- kapan AI boleh aktif lagi
  paused_at timestamptz DEFAULT now(), -- kapan di-pause
  paused_by text DEFAULT 'unknown'  -- siapa yang trigger:
                                    --   manual_reply_bypass, manual_reply_sumber,
                                    --   admin_628xxx, cloud_api_status, fonnte_auto
);

CREATE INDEX IF NOT EXISTS idx_wa_paused_until ON wa_paused (paused_until);

4. CARA KERJA — FLOW
================================================================================

TRIGGER OTOMATIS (admin balas dari HP):
─────────────────────────────────────
1. Admin cabang Bypass balas chat customer 628xxx dari HP
2. Fonnte kirim webhook dengan isFromMe=true, target=628xxx
3. api/wa/webhook.js detect outgoing → setHumanTakeoverLocal(628xxx)
4. persistHumanTakeover(628xxx, 'manual_reply_bypass') → upsert ke wa_paused
5. Customer 628xxx kirim pesan ke cabang MANAPUN (Bypass/Sumber/CSB/dll)
6. isHumanTakeover(628xxx) → cek local Map → fallback Supabase wa_paused
7. Ditemukan record aktif → AI SKIP, tidak balas
8. Setelah 30 menit → record expired → AI aktif kembali

TRIGGER MANUAL (admin command):
─────────────────────────────
1. Admin kirim "/ai_off 628xxx 60" ke nomor WA bot
2. handleAdminCommand() detect → cek admin number → valid
3. Upsert ke wa_paused: sender=628xxx, paused_until=+60min, paused_by=admin_628xxx
4. Kirim konfirmasi ke admin: "AI dimatikan untuk 628xxx selama 60 menit"
5. Semua cabang langsung respect karena shared Supabase table

RESUME MANUAL:
─────────────
1. Admin kirim "/ai_on 628xxx"
2. Delete dari wa_paused + clear local cache
3. AI langsung aktif kembali untuk 628xxx di semua cabang

MONITORING:
──────────
1. Admin kirim "/ai_status"
2. Query wa_paused WHERE paused_until > now()
3. Tampilkan list: nomor, sisa menit, siapa yang trigger

5. ADMIN COMMANDS
================================================================================

Semua commands berlaku di SEMUA CABANG via Supabase shared state.
Bisa dipakai dari WhatsApp Cloud API maupun Fonnte webhook.

  /ai_off 628xxx [menit]  — Matikan AI untuk customer (default 30 menit)
  /ai_on 628xxx           — Hidupkan kembali AI untuk customer
  /ai_status              — Lihat semua customer yang AI-nya sedang OFF
  /ai_help                — Tampilkan daftar commands

Contoh:
  /ai_off 628123456789        → AI off 30 menit
  /ai_off 628123456789 60     → AI off 60 menit
  /ai_on 628123456789         → AI on kembali
  /ai_status                  → List semua yang sedang di-pause
